Design Workflow

The six modules are meant to be worked in sequence — each stage produces the numbers the next stage needs. All of it runs entirely in your browser: nothing is uploaded anywhere, and the working set of numbers is kept in localStorage so every tab reads the same aircraft.

STEP 1

Size the Airframe

Start in Sizer. Enter target weight, aspect ratio and wing cubic loading to get a first-pass wing area, span and chord. These feed every other module.

STEP 2

Select an Airfoil

In Airfoil, pick a NACA 4-digit section (or Clark-Y) and check lift, drag, stall angle and aerodynamic-center estimates at your cruise condition.

STEP 3

Match the Powertrain

Electronics sizes motor/prop/battery against the all-up-weight (AUW) pulled from the Sizer, and estimates thrust-to-weight, current draw and flight time.

STEP 4

Balance the CG

CG Analysis sums component moments about the nose datum, plots CG against the wing's neutral point, and reports static margin.

STEP 5

Check the Gear

Landing Gear checks prop-strike clearance, tip-back (rotation) angle and lateral overturn angle against the CG height and position.

STEP 6

Review in 3D

The 3D Viewer renders a live, parametric model — wingspan, chord, fuselage length and CG marker all update from your saved state.

How State Sync Works

Every module reads/writes one shared object in localStorage (key rcSizerSuite.v1) via a small helper, state.js. When you change a value on one tab, it's saved immediately; open another tab and it reads the same value on load, and updates live if both tabs are open at once (via the browser's storage event).

Nothing here leaves your machine — there is no server component. Clearing your browser's site data resets the suite to its defaults.

Reading the Citation Marks

Small circular i marks sit next to formula outputs throughout the suite. Hover or focus one to see the engineering source for that number — a textbook (Raymer, Anderson, Abbott & Von Doenhoff), a named method (Thin Airfoil Theory, Wing Cubic Loading), or an empirical dataset (UIUC Propeller Database).

Where a formula is a rule-of-thumb rather than a rigorous derivation, the note says so directly — treat those as first-pass estimates to validate against test data or higher-fidelity tools (XFOIL, AVL, or a wind-tunnel/whirl-rig test) before committing to hardware.
